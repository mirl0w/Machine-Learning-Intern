Content Opportunity Scoring: A Ranked Review System for Declining Pages

Mariam Abdelaleem — FlyRank ML Internship, Applied Search Intelligence Track — 2026

Abstract. This work builds a system to rank website content pages by likelihood of search visibility decline, so that content teams with limited review capacity can prioritize which pages to examine first. Using an anonymized 30,000-row slice of real search performance data, I built a transparent hand-written baseline rule, then trained a Decision Tree and Random Forest classifier under a client-holdout validation design to avoid overfitting to individual clients. The Random Forest reached a Precision@50 of 0.72, compared to the baseline's 0.44 — roughly a 1.6x improvement in identifying genuinely declining pages among the top 50 flagged. Results are presented as decision-support evidence for human-reviewed content prioritization, not as proof of causal effect or search-engine ranking factors.

1. Introduction / Problem Statement

Content teams managing large websites face a simple but costly problem: which pages, out of thousands, are worth reviewing first? Manually auditing every page is infeasible, and a wrong prioritization has real cost — a genuinely declining page that goes unreviewed continues losing visibility silently, while reviewer time spent on healthy pages is time not spent elsewhere. This project builds a ranked review system that scores pages by their likelihood of decline, so a reviewer can focus attention on the highest-value candidates first.

2. Data

This work uses the FlyRank ML Internship starter dataset: a 30,000-row anonymized slice of real, pseudonymized search and content performance data, filtered to pages with observed search impressions and at least 90 days of content age. The dataset ships only observable signals — real measurements such as impressions, clicks, position, and content age — never FlyRank's internal product decision flags (such as health scores or priority rankings), which were deliberately excluded from the release to prevent circular results.

The broader FlyRank internship warehouse (a ~79 million row release covering ~70 clients and ~427,000 content items) was explored during an earlier data-contract exercise to verify schema, grain, and data availability, but the modeling work reported here uses the smaller starter slice.

3. Methodology

Label: a page is labeled "declining" if its recent trend direction is downward. This is a snapshot-based proxy label rather than a validated future-window outcome — a limitation discussed further below.

Features (all observable at decision time, before any outcome is known): content age, days since last update, 90-day impressions, average search position, click-through rate, and word count.

Baseline: a transparent hand-written rule flagging pages that are simultaneously stale (not updated in 180+ days) and still visible (500+ impressions), or visible with a weak click-through rate (below 0.3).

Model: a Decision Tree (max depth 4) and a Random Forest (200 trees), both weighted to handle label imbalance.

Validation design: a client-holdout (grouped) split, ensuring pages belonging to the same client never appear in both training and test sets — so the model is evaluated on clients it has never seen, matching real deployment conditions.

Leakage audit: all features were confirmed to be knowable before any outcome was observed. A deliberate leakage experiment — feeding a label-derived signal into the model as if it were a normal feature — was performed and showed an artificially inflated, meaningless result, confirming the importance of this check.

4. Results

Precision@K measures how many of the top K ranked pages were genuinely declining. All results below are reported under the honest client-holdout validation split.

MethodPrecision@20Precision@50
Baseline (hand-written rule)0.450.44
Decision Tree0.550.60
Random Forest0.800.72

The Random Forest outperformed the baseline at both thresholds, reaching Precision@50 of 0.72 versus the baseline's 0.44 — an observed 1.6x improvement — and Precision@20 of 0.80 versus 0.45, nearly double. This suggests the model is especially effective at identifying the very highest-priority pages, which matters most when review capacity is most limited.

5. Limitations

This work does not claim that content refreshes cause traffic recovery — no causal experiment was run, only observational patterns. It does not claim to reflect Google's actual ranking algorithm. Results should not be assumed to generalize beyond this specific 30,000-row slice or its represented clients.

Validation design measurably affected the result: under a naive random train/test split (ignoring which client each page belonged to), the Decision Tree reached Precision@50 of 0.660. Under the honest client-holdout split, this dropped to 0.600. This gap indicates the naive split was somewhat optimistic — the model was likely picking up some client-specific patterns that don't transfer to genuinely unseen clients. The client-holdout number is the one that should be trusted as a realistic estimate.

The label itself is a snapshot proxy (current trend direction), not a validated future-window outcome. A stronger next iteration would define decline as a measured drop over a defined future period (e.g., the next 30 days), which this version does not yet implement.

6. Ranked Recommendations

Based on model output, pages are mapped into four action categories:

  • refresh_content — stale and still-visible pages; highest priority
  • rewrite_title_meta — visible pages with strong search position but weak click-through rate
  • review_priority — elevated model-flagged risk without one clear cause
  • monitor — low priority, no action required now

Every flagged page requires human review before any content change is made — this system surfaces candidates for review, it does not approve or execute edits automatically. The following should never be automated based on this model alone: publishing content changes, deleting or de-indexing pages, or treating a high score as proof that a refresh will cause recovery.
